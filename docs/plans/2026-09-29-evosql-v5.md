### Task 1: Decision check, gap-only discovery and the verified set

- [ ] **Gap check.** When step 1 finishes, report gap = hints − docs on the final set, official gold.
  - If gap < 4, stop here: write the v5 finding into the README and skip the remaining steps (spec §3).
- [ ] **`facts.py`: "already in docs".** In `check_fact(fact, db)`, for `constraint` and `encoding` facts, find the docs line of each named column: `column_docs` is kept on `Database` as `db.column_notes`, {table: {column: text}}. Drop the fact with "already in docs" when every number and quoted value in its text appears in one of those lines.
- [ ] **`learn.py`: proposer prompt.** Add one rule: "Do not restate anything the column docs or value profile already say; write only conventions (how ages, dates and counts are computed), stored codes that differ from documented symbols, phrase meanings, row grain and join paths."
- [ ] **`learn.py`: verify.**
  - `discover_facts` keeps the kept facts of each question as bundles. After the batches, `verify(bundle_qid, facts) -> bool` re-answers that question with `AllFacts(FactBook(bundle))` and checks it against gold.
  - It returns `(single, verified, conflicts)`:
    - `single = merge(all kept facts)`;
    - `verified = merge(facts of bundles that passed)`.
  - It logs `{"event": "verify", "qid", "facts", "passed"}`.
  - In `discover(cfg)`, `verify` uses the real agent and the cache. It saves `knowledge_single.json` and `knowledge_verified.json`, and deletes both files at the start of a run.
- [ ] **Tests:**
  - "already in docs": a range fact that restates its column's doc range is dropped; a convention fact naming the same column is kept.
  - `discover_facts` with a fake `verify` that passes one question: `single` holds both bundles, `verified` holds only the passing bundle, and verify events are logged.
- [ ] Commit: `feat: v5 gap-only discovery with single and verified knowledge sets`.

### Task 2: Arms per knowledge set, gate and report

- [ ] **`config`:** `protocol.arms: [docs, hints, retrieve@single, retrieve@verified]`, with `split_arm(arm) -> (mode, variant | None)`.
- [ ] **`evaluate.py`:**
  - `run_mode(cfg, arm, set_name)` loads `knowledge_{variant}.json` for knowledge arms and logs to `{set}_{arm}.jsonl`. The setup digest is unchanged (facts plus search settings).
  - `load_results` iterates over `cfg["protocol"]["arms"]`.
  - `gate` runs docs and every `@` arm on the gate set. Candidates and tie order follow the order of `arms`, so ties go to `single`. It writes `gate.json`.
  - `analyze`:
    - the first line says "diagnostic: final set reused (seen in the v4 analysis and label review)";
    - a new "gap closed" column: (arm − docs) / (hints − docs);
    - the knowledge summary lists both sets, the "already in docs" drops, and the verify pass count.
- [ ] **CLI:** `run --arm A.. --set S` (choices = `protocol.arms`); `gate`; `analyze`.
- [ ] **README:** a v5 section with the finding from step 1, the arms, the commands, and a note that the final set is diagnostic.
- [ ] **Tests (update the v4 ones where names changed):**
  - arm parsing and per-arm log and knowledge file names;
  - the gate's tie order follows `arms` (single before verified);
  - the gap-closed value in the report from fixed records.
- [ ] Commit: `feat: v5 arms per knowledge set, gate and diagnostic report`.
