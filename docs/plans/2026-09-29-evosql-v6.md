# EvoSQL v6 Implementation Plan

> Executed inline. User rules:
> - three coarse tasks, with one review at the end;
> - targeted tests only;
> - simple code, one-line comments;
> - no paid runs except a 2–5 question smoke test after setup.

**Goal:** implement `docs/specs/2026-09-29-evosql-v6-design.md`: a streaming, per-database fact memory versus no memory, on 4 Arcwise-Plat databases, in 2 orders, within $2.

**Architecture:**
- **Reused:**
  - the agent loop (`agent.py`), LLM client, budget and cache;
  - SQL execution and value profile with column docs (`bird.py`);
  - fact checks and merge (`facts.py`), and hybrid search (`search.py`).
- **New modules:**
  - `memory.py`: eligibility, selection, credit, retirement and the pre-check;
  - `stream.py`: the test-then-train loop;
  - `report.py`: per-stream analysis.
- **Resume:** replay from scratch. Every LLM reply and embedding is cached, and the stream is deterministic, so rerunning costs nothing.
- **Old versions:** v5 is tagged `v5`; the v5 modules stay untouched except for the shared changes listed here.

### Task 1: Data layer, structured facts, the one-fact proposer

- [ ] **`scripts/get_v6_data.py`:**
  - download BIRD `dev.zip` (~346 MB) and extract only the 4 database folders into `data/bird_dev/<db>/`, leaving thrombosis intact; delete the zips;
  - download `arcwise_plat_full_with_diff.json` and the 4 databases' corrected `database_description/*.csv` into `data/arcwise/`;
  - write `data/arcwise/manifest.json` with the Arcwise commit SHA and the SHA-256 of every file used.
- [ ] **`bird.py`:**
  - `load_arcwise(path, dbs) -> [Question]`;
  - `open_db(..., docs_dir)` reads the column descriptions from `docs_dir` when given.
- [ ] **`facts.py`:**
  - `Fact.values: list | None`;
  - when `values` is a list, grounding checks only those `{table, column, value}` entries and ignores quoted text (v4/v5 facts keep the quoted check);
  - a fact must name a table or column of the schema.
- [ ] **`learn.py`:**
  - `propose_one(llm, db, q, agent_sql, facts) -> Fact | None`, using the gap-only prompt;
  - the prompt asks for exactly one fact with `applies_to` and `values`, and a `COUNT(*)` evidence query for facts about absence;
  - `leak_exempt(fact, db)` lists values allowed despite equalling an answer: structured, grounded, and in ≥ 2 rows of their column. `check()` passes them to `leaks`.
- [ ] **Tests:**
  - structured values: an ungrounded value is dropped, quoted prose is ignored;
  - a non-unique code equal to the answer is allowed, a unique value is rejected;
  - `propose_one` parses one fact with values, from a fake reply;
  - `load_arcwise` filters by database, from a fixture.
- [ ] Commit: `feat: v6 data layer, structured fact values and one-fact proposer`.

### Task 2: Fact memory and the stream

- [ ] **`memory.py`, `FactMemory(db, embed, cfg)`:**
  - **State per fact:** score, uses, zero-effect uses, retired reason.
  - `phrase_hit(fact, q, history)`:
    - whole-phrase match with word boundaries;
    - genericity: a phrase matching more than 25% of the earlier questions (once there are ≥ 8) needs a second cue;
    - grain/relation facts need schema scope.
  - `semantic_hit(fact, q)`: proven facts only; cosine ≥ 0.75, a margin of ≥ 0.05 over the next fact, and schema scope.
  - `select(q, history)`: proven facts first; at most 1 unproven fact; at most 2 in total.
  - `credit(ids, facts_ok, none_ok)`: applies the retirement rules (first regression if unproven; −2 if proven; 5 zero-effect uses).
  - `precheck(fact, earlier, answer_with)`: up to 2 matched earlier questions; reject on any regression; count fixes toward the score.
  - `add(fact)`: merges with the active facts.
- [ ] **`stream.py`, `run(cfg)`:**
  - for each seed, then each database: shuffle, then for each question:
    1. none answer (cache-shared across orders);
    2. facts answer with `memory.select`;
    3. score both;
    4. credit;
    5. if the facts arm failed: propose one fact, check, pre-check (skipped when the order's allocation is within $0.10), add.
  - write `runs_v6/stream_s{seed}_{db}.jsonl` with one record per question: position, both results, injected fact IDs, usage, learning events;
  - save each stream's final facts with their state.
- [ ] **CLI:** `python -m evosql --config configs/v6.yaml stream` and `report`.
- [ ] **Tests:**
  - eligibility: "age" does not match "average"; a generic phrase needs a second cue; grain facts need scope, mappings do not; the semantic path works for proven facts only;
  - selection caps;
  - each retirement rule;
  - the pre-check rejects on regression and counts fixes;
  - stream (fake LLM, toy database): a fact learned from question q is never used on q, it is used on a later matching question, and pre-checks are skipped past the allocation.
- [ ] Commit: `feat: v6 fact memory and streaming runner`.

### Task 3: Report and README → review

- [ ] **`report.py` → `results_v6/summary.md`:**
  - per stream: second-half accuracy for none and facts, the difference, fixes and regressions, and a learning curve by quarter;
  - direction count and pooled mean;
  - block bootstrap over streams, and leave-one-database-out;
  - heuristic question-level sign-flip test and clustered CI, labelled as heuristic;
  - injection rate per stream, with the inert flag below 10%;
  - cost, latency and turns;
  - facts: dropped by check, pre-check outcomes, retired facts with reasons, final facts verbatim;
  - the pinned manifest.
- [ ] **README:** a v6 section with the claim, the flow, the commands and the $2 budget.
- [ ] **Tests:**
  - direction count and second-half difference from fixed records;
  - injection-rate inert flag.
- [ ] Commit: `feat: v6 report`.
- [ ] **Review:** one review of v6 against the spec; apply fixes; commit.
- [ ] **Setup:** run `get_v6_data.py` (approved; print URLs and sizes), check the manifest, then a smoke test on 2–3 questions of one database.
