# EvoSQL v3 Implementation Plan

> Executed inline (superpowers:executing-plans). Per user preference: 3 coarse tasks, reviews only after Tasks 2 and 3, targeted tests only, simple code with one-line comments. Interfaces and pseudocode instead of full code.

**Goal:** Implement `docs/specs/2026-09-29-evosql-v3-design.md`: typed facts learned on 50 questions, frozen, and tested on 50 other questions against 3 baselines, within $1.

**Architecture:** Four new, small modules sit on top of the existing agent, BIRD helpers and LLM client:
- `split.py`: the learning/test split;
- `facts.py`: the knowledge format and its free checks;
- `learn.py`: the gated versioned loop;
- `evaluate.py`: the test arms and the report.

The learning loop is a pure function over injected callables (solve, propose, consolidate), so it can be unit-tested with stubs. Reruns are cheap because every LLM call is cached, and a persisted spend guard enforces the $1 cap.

**Tech stack:** existing (Python 3.13, uv, openai SDK against DeepSeek, pytest).

### Task 1: Split, facts, config

**Files:** `configs/base.yaml`, `src/evosql/split.py`, `src/evosql/facts.py`, `tests/test_split.py`, `tests/test_facts.py`

- [ ] Config:
  - `agents.deepseek_v3`: model `deepseek-flash`, thinking disabled, `value_profile: true`, prices, `runs_dir: runs_v3`, `results_dir: results_v3`.
  - `v3: {agent_profile: deepseek_v3, n_learn: 50, n_test: 50, seed: 0, epochs: 2, batch_size: 5, min_gain: 2, budget_usd: 1.0, selfcons_max_n: 5}`.
  - Add `runs_v3/` and `results_v3/` to `.gitignore`.
- [ ] `split.py`:
  - `make_split(questions, n_learn, n_test, seed) -> {"learn": [qid], "test": [qid]}`.
    - Sample `n_learn + n_test` questions stratified by difficulty (largest-remainder allocation, per-difficulty shuffle with `Random(seed)`).
    - Sort the sample by difficulty, then alternate learn/test, so both halves keep the mix and have exact sizes.
  - `save_split(path, split)` and `load_split(path)` (JSON).
- [ ] `facts.py`:
  - `Fact(id, kind, subject, fact, source_qids)`; `KINDS = ("mapping", "constraint", "encoding", "meaning")`.
  - `FactBook(facts, next_id)`:
    - `apply(edits) -> FactBook` (copy). Edits are dicts `{op: add|modify|delete, id, kind, subject, fact, qid}`; unknown ids are ignored.
    - `render()`: `"Learned database knowledge:"`, then facts grouped by subject as `  - [kind] fact`. Returns `""` when empty.
    - `total_tokens()`, `save(path)`, `load(path)`, `adds()` (for the ungated book).
  - `check_fact(fact, db, question=None, gold_sql=None, gold=None) -> reason | None`:
    1. **SQL:** a case-sensitive regex for `SELECT|FROM|WHERE|JOIN|GROUP BY|ORDER BY|LIMIT|DISTINCT|COUNT(` gives `"contains SQL"`. Case-sensitive, because "from" is ordinary English.
    2. **Grounded:** a `Table.Column` subject must exist (table in `db.tables`, column in `PRAGMA table_info`), else `"unknown column"`. Each `'literal'` in the fact must occur, as text, in the subject column or any `Table.Column` named in the fact (or in any column if none is named), else `"value not in data"`.
    3. **Leakage** (when a question is given): reuse `learner.leaks(Edit("add", when="", text=fact.fact), ...)`.
- [ ] Tests:
  - split: exact sizes, no overlap, difficulty counts within ±1 of the proportional share, the same seed gives the same split;
  - facts:
    - SQL keywords rejected, lowercase "from" allowed;
    - unknown column rejected;
    - a literal missing from the column rejected, a present one accepted;
    - render groups facts by subject;
    - apply add/modify/delete.
- [ ] `uv run pytest`; commit `feat: v3 split and typed facts with data checks`.

### Task 2: Learning loop, spend guard, CLI → review

**Files:** `src/evosql/llm.py`, `src/evosql/budget.py`, `src/evosql/learn.py`, `src/evosql/__main__.py`, `tests/test_learn.py`

- [ ] `llm.py`: add `self.fresh = {prompt_tokens, completion_tokens, provider_cached_tokens}`, incremented only on network calls (not on cache hits).
- [ ] `budget.py`: `Budget(path, cap_usd)`:
  - `charge(llms_with_prices)` adds the new fresh spend since the last charge and persists the total in `spend.json`;
  - it raises `BudgetExceeded` when the total passes the cap.
- [ ] `learn.py`:
  - `PROPOSER_V3`: static instructions (the four fact kinds with examples, "state facts about the data, never the SQL fix", skip the gold SQL when it looks like an annotation error, reply JSON), then schema, value profile, current facts (with ids), then the batch (question, agent SQL, gold SQL per qid).
    - Reply format: `{"items": [{"qid": 1, "skip": "reason"} | {"qid": 1, "edits": [{"op": "add", "kind": "...", "subject": "...", "fact": "..."}]}]}`.
  - `propose_facts(llm, db, book, batch) -> (edits, skips)`; returns `([], [])` on unparsable JSON.
  - `CONSOLIDATE_V3` and `consolidate(llm, db, book) -> FactBook`: rewrite into non-duplicate, non-contradicting facts in the same format; each is checked with `check_fact` (SQL and grounding only).
  - `learn_loop(learn_qs, solve, propose, consolidate, check, epochs, batch_size, min_gain, log)`, pure:
    ```
    f = flips(score(K0), score(K0 + NEUTRAL))       # calibration
    threshold = max(min_gain, f)
    for epoch: scores = score(K); failures = wrong in split order
      for batch: edits, skips = propose(batch, K); keep edits passing check; ungated += passing adds
        if no edits: log and continue
        cand = K.apply(edits); cs = score(cand); net = right(cs) - right(scores)
        accept = net >= threshold and any(cs[q] for q in batch)
        log(...); if accept: K, scores = cand, cs
    C = consolidate(K); if right(score(C)) >= right(score(K)): K = C
    return K, ungated, f
    ```
    `score(book)` maps every learning question to `solve(q, book)`. `solve` answers with the agent and scores with `exec_match`.
  - `run_learn(cfg)`:
    - wires the real LLMs, the Budget and the logger (`runs_v3/learn.jsonl`, rewritten on each run);
    - saves `knowledge_vN.json` per accepted version, plus `knowledge_final.json`, `ungated.json` and `calibration.json`;
    - on `BudgetExceeded` it stops cleanly (a rerun replays from cache).
- [ ] `__main__.py`:
  - `split` writes `runs_v3/split.json`;
  - `learn` calls `run_learn`;
  - v3 commands default to `--agent deepseek_v3`.
- [ ] Tests (stub `solve` from a lookup table, stub `propose`/`consolidate`):
  - a candidate with net gain below the threshold is rejected;
  - a gain above the threshold that fixes no batch question is rejected;
  - a qualifying candidate is accepted, and K advances;
  - consolidation with a lower learning score is discarded (K kept), and with an equal score it is kept;
  - ungated collects every passing add, including ones from rejected batches;
  - the budget raises past the cap, and its total persists across instances.
- [ ] Commit `feat: v3 learning loop with gated versions, consolidation and spend guard`.
- [ ] **Milestone review** (code-reviewer against spec sections 3–5).

### Task 3: Test arms, analysis, README → review

**Files:** `src/evosql/evaluate.py`, `src/evosql/__main__.py`, `README.md`, `tests/test_evaluate.py`

- [ ] `evaluate.py`:
  - `run_test(cfg, arm)`: loads the split and the arm's knowledge (docs and selfcons: empty; evosql: `knowledge_final.json`; ungated: `ungated.json`). It answers each test question and appends `runs_v3/test_<arm>.jsonl` (qid, difficulty, sql, correct, usage). It resumes by skipping qids already logged, charges the Budget and shows a progress bar.
  - `selfcons_n(cfg)`: `min(selfcons_max_n, max(1, round((learn_usd + evosql_test_usd) / n_test / docs_usd_per_q)))`. It raises a clear error if the docs or evosql logs are missing.
  - `where_columns(sql, columns)`: the column names that occur in the WHERE ... (up to GROUP/ORDER/LIMIT) part. `twins(split, questions, db)` returns the set of test qids that share a WHERE column with any learning question.
  - `analyze_v3(cfg)` writes `results_v3/summary.md`:
    - per arm: accuracy, bootstrap 95% CI, McNemar p against docs (paired by qid), test $, $ per correct answer (evosql and ungated include amortized learning $);
    - the twin / no-twin accuracy table;
    - the knowledge summary (fact count, tokens, count by kind, check failures by reason, skips, accepted/rejected versions from `learn.jsonl`, calibration f);
    - the final facts, verbatim.
- [ ] `__main__.py`: `test --arm docs|evosql|ungated|selfcons` and `analyze-v3`.
- [ ] README: a "v3 protocol" section with the 5 commands and what each arm means.
- [ ] Tests:
  - `where_columns` finds only filter columns (not SELECT columns);
  - `twins` marks a test question that shares a filter column;
  - `run_test` resumes without duplicates (fake LLM);
  - `selfcons_n` follows its formula and cap.
