# EvoSQL v1 Implementation Plan

> Executed inline (superpowers:executing-plans). Per user preference: 4 coarse tasks, reviews only after Tasks 2 and 4, targeted tests only, simple code with one-line comments. Interfaces and pseudocode instead of full code.

**Goal:** Build the streaming Text2SQL learner and its 5 arms from `docs/specs/2026-09-28-evosql-design.md`, runnable on Groq free models, resumable and cache-first.

**Architecture:** Small flat package `evosql/`. A cached OpenAI-compatible client feeds a tool-loop SQL agent. A gate (with switches) decides which learned notes to keep. A prequential runner writes one JSONL line per question and can resume. A single analysis module turns JSONL into curves and stats.

**Tech stack:** Python 3.13, uv, openai SDK (Groq base URL), PyYAML, python-dotenv, numpy, scipy, matplotlib, pytest.

---

## File map

```
evosql/
  pyproject.toml, .gitignore (.env, data/, runs/, cache/, results/)
  scripts/get_bird.sh           # downloads BIRD dev only (asks user first)
  configs/base.yaml             # provider, models, databases, limits
  configs/arms/{vanilla,docs,ratchet,evosql,selfcons}.yaml
  evosql/
    bird.py        # load questions + docs, read-only SQL exec, exec_match
    llm.py         # cached chat client, backoff, usage counters
    agent.py       # tool-loop agent, self-consistency vote
    knowledge.py   # Note, Edit, Knowledge (render, apply, save/load)
    learner.py     # proposer, leakage check, Gate (accept + prune)
    stream.py      # prequential runner with resume, noise calibration
    analysis.py    # curves, CIs, McNemar, cost, charts, self-consistency N
    __main__.py    # CLI: run / calibrate / analyze
  tests/
```

Deviation from the spec: the schema DDL goes straight into the system prompt, so the `list_tables` tool is dropped (one fewer call per question).

### Task 1: Scaffold, BIRD data, SQL execution

**Files:** `pyproject.toml`, `.gitignore`, `scripts/get_bird.sh`, `configs/base.yaml`, `evosql/bird.py`, `tests/test_bird.py`

**Steps**
- [ ] Scaffold with `uv init --package`; add dependencies; `.gitignore`.
- [ ] HEAD-check the BIRD dev URL for its size, **ask the user**, then run `scripts/get_bird.sh` to fetch dev only into `data/bird_dev/`.
- [ ] `bird.py`:
  - `Question(qid, db_id, question, gold_sql, difficulty)`; evidence dropped at load.
  - `load_questions(data_dir, db_id) -> list[Question]`; `db_counts(data_dir) -> dict` (pick the top 4 databases).
  - `schema_ddl(db_path) -> str` (CREATE statements from `sqlite_master`).
  - `table_docs(data_dir, db_id, table) -> str` (column-description CSV; `errors="replace"` for bad encodings).
  - `execute(db_path, sql, timeout=30) -> (rows, error)`: read-only URI `mode=ro`; timeout via `set_progress_handler`.
  - `exec_match(db_path, pred_sql, gold_rows) -> bool`: BIRD semantics `set(pred) == set(gold)`; an erroring prediction is False.
  - `gold_rows(db_path, q)`: cached as JSON under `cache/gold/` so slow gold queries run once.
- [ ] Tests (`tests/test_bird.py`, on a tiny temp SQLite DB):
  - exec_match ignores row order and duplicate rows, and treats `NULL == NULL`;
  - a different value or an erroring prediction gives False;
  - a write statement (`DELETE`) fails on the read-only connection;
  - a slow recursive CTE hits the timeout and returns an error, not a hang.
- [ ] `uv run pytest` passes; commit `feat: scaffold, BIRD loader and SQL execution`.

### Task 2: LLM client, agent, knowledge + smoke test  → review

**Files:** `evosql/llm.py`, `evosql/agent.py`, `evosql/knowledge.py`, `configs/arms/*.yaml`, `evosql/__main__.py` (`run --limit` for the smoke test only), `tests/test_llm.py`, `tests/test_agent.py`, `tests/test_knowledge.py`

**Steps**
- [ ] `llm.py`: `LLM(base_url, api_key, model)` with `chat(messages, tools=None, temperature=0, sample=0) -> dict`
  - Cache key = sha256 of (model, messages, tools, temperature, sample); stored at `cache/llm/<key>.json`.
  - A cache hit makes no network call, but its usage is still counted (logical cost) and flagged `cached`.
  - On 429 or 5xx, back off exponentially for up to 6 tries, then raise `ProviderExhausted`.
  - `usage` counter: calls, prompt_tokens, completion_tokens.
- [ ] `knowledge.py`:
  - `Note(id, when, text, source_qid, credited_qids, created_step)` with `tokens = len(when + text) // 4`.
  - `Edit(kind: add|modify|delete, note_id, when, text)`.
  - `Knowledge`: `apply(edit, step, qid) -> Knowledge` (returns a copy), `without(note_id)`, `render()`, `total_tokens()`, `save(path)`, `load(path)`.
- [ ] `agent.py`: `answer(llm, db, question, knowledge, docs, temperature=0, sample=0) -> AgentResult(sql, steps, error)`
  - System prompt = rules + schema DDL + `knowledge.render()`.
  - Tools:
    - `describe_table(table)`: 3 sample rows, plus docs if the arm has them;
    - `profile_column(table, column)`: nulls, distinct count, top 10 values, min/max;
    - `run_sql(sql)`: first 20 rows or the error;
    - `submit(sql)`.
  - If there are no `tool_calls`, parse `{"tool":..,"args":..}` JSON from the content; else nudge once.
  - At step 7, tell the model it must submit. Stop after 8 steps; no submit means `sql=None`.
  - `answer_self_consistent(..., n)`: n samples at temperature 0.7; vote by the frozenset of result rows; return the SQL of the biggest group.
- [ ] Arm YAMLs: `docs`, `learning` (none|ratchet|gated), gate switches, `self_consistency_n`.
- [ ] Tests:
  - `test_llm`: a second identical call is served from the cache with zero transport calls, and still counts usage;
  - `test_agent` (fake LLM with scripted replies):
    - `run_sql` then `submit` returns the submitted SQL;
    - a JSON-in-content fallback is parsed;
    - never submitting gives `sql=None` after 8 steps;
    - majority vote picks the biggest result group;
  - `test_knowledge`: add/modify/delete work, and a save/load round-trip keeps ids and the next id.
- [ ] Pick Groq models: list the models via the API, then run `python -m evosql run --arm docs --db <top db> --limit 20` for candidate agent models. Put the chosen agent/proposer models in `configs/base.yaml`.
- [ ] Commit `feat: cached LLM client, SQL agent, knowledge notes`.
- [ ] **Milestone review** (code-reviewer against the spec, Sections 7, 8 and 10).

### Task 3: Learner, gate, streaming runner

**Files:** `evosql/learner.py`, `evosql/stream.py`, `evosql/__main__.py` (`run`, `calibrate`), `tests/test_learner.py`, `tests/test_stream.py`

**Steps**
- [ ] `learner.py`:
  - `propose(llm, q, wrong_sql, gold_sql, knowledge) -> Edit | None`: JSON output; None when unparsable.
  - `leaks(edit, question_text, gold_sql, gold_rows) -> str | None`. Two rules:
    1. A result value (≥2 characters) that does **not** appear in the gold SQL shows up as a whole word in the note. Filter constants from the gold SQL (e.g. `'Fresno'`, `1`) are allowed, since they are real knowledge.
    2. The note shares a 5-word run with the question text.
  - `GateConfig(replay_k, noise_p, leakage_check, token_check, max_note_tokens=80, cap_tokens, prune_every)`.
    - Ratchet config = `replay_k=0, noise_p=0`, all checks off, `prune_every=0`, `cap_tokens=None`.
  - `Gate(cfg, solve)` where `solve(question, knowledge) -> bool` is injected (it runs the agent and exec_match). `accept(edit, q, knowledge, seen, step) -> (Knowledge, decision, reason)`:
    ```
    leakage / token checks  -> reject
    if cap and total + note > cap: knowledge = prune(knowledge); still over -> reject
    replay = [q] + last replay_k seen questions whose gold SQL shares a table with q
    before = [solve(x, knowledge)]; after = [solve(x, candidate)]
    non-delete and not after[q] -> reject "does not fix q"
    need = 0 if delete else 1 + round(noise_p * len(replay))
    gain >= need -> accept; credited = [q] + replay questions flipped False→True (max 5)
    ```
  - `prune(knowledge, questions_by_id)`: for each note, compare accuracy on its credited questions with and without it; drop the note if accuracy without ≥ accuracy with.
- [ ] `stream.py`: `run_arm(cfg, arm, db, order_seed, limit=None)`
  - Order = `random.Random(seed).shuffle(questions)`.
  - Resume: count the lines already in `runs/<arm>/<db>/order<k>.jsonl` and load `order<k>.notes.json`; continue from there.
  - Per step:
    - answer (or self-consistency) → score → learn if the arm learns and the answer is wrong → prune every `prune_every` → append the JSONL line → save the notes.
    - The JSONL line holds: step, qid, sql, correct, answer usage, learn usage, notes count/tokens, edit, decision, reason, model.
  - `ProviderExhausted` → flush and exit with a message to rerun later.
  - `calibrate(cfg, db)`: docs arm, first 20 questions of order 0, `sample=0` vs `sample=1`; writes `runs/noise/<db>.json` with `p`. The evosql arm reads it.
- [ ] Tests:
  - `test_learner` (stub `solve` from a lookup table):
    - leakage flags an answer value but allows a gold-SQL constant, and flags a 5-word question overlap;
    - gate accepts a note that fixes q plus one replay question;
    - gate rejects a note that fixes q but breaks two replay questions;
    - the ratchet accepts that same note;
    - a delete is accepted at zero gain;
    - prune drops a note whose removal loses nothing;
    - the cap rejects when still over after pruning;
  - `test_stream`: a fake solver raises `ProviderExhausted` at step 3; a rerun continues from step 3; the final JSONL has N unique steps, and the notes survive.
- [ ] Commit `feat: gated learner and resumable prequential runner`.

### Task 4: Arms end-to-end, analysis, README  → review

**Files:** `evosql/analysis.py`, `evosql/__main__.py` (`analyze`), `README.md`, `tests/test_analysis.py`

**Steps**
- [ ] `analysis.py`:
  - load every JSONL file;
  - cumulative and rolling-20 accuracy curves per arm (mean across orders);
  - final-third accuracy with a bootstrap 95% CI (resample orders, then questions);
  - paired McNemar between arms (`scipy.stats.binomtest` on discordant pairs, matched by qid);
  - tokens and calls per correct answer, split into answer vs. learn;
  - note count over steps; accept/reject counts by reason;
  - leakage rate of the ratchet's final notes (via `leaks` on each note's source question);
  - `selfcons_n(db)` = round(evosql tokens per question / docs tokens per question), capped at 7;
  - warn if a run's JSONL has more than one model ID;
  - PNG charts plus `results/summary.md`.
- [ ] Tests: McNemar on a hand-built paired table matches a known p-value, and the bootstrap CI contains the true mean on synthetic data.
- [ ] Staged run (spec Section 8): 1 database, 1 order, all 5 arms; check that the JSONL and charts look sane.
- [ ] README: pitch, method, how to run, a results placeholder filled from `results/summary.md`, and the honest-framing note.
- [ ] Commit `feat: analysis, charts and README`.
- [ ] **Milestone review** (code-reviewer on the whole v1 against the spec).
- [ ] Full run (all databases and orders) happens afterwards over several days; not part of this plan.
