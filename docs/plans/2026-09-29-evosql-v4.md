# EvoSQL v4 Implementation Plan

> Executed inline. User rules: 3 coarse tasks, reviews only after Tasks 2 and 3, targeted tests only, simple code, one-line comments. Interfaces and pseudocode, not full code.

**Goal:** implement `docs/specs/2026-09-29-evosql-v4-design.md`: single-pass discovery of verified typed facts, then four delivery modes (docs, all, retrieve, tool), a one-shot gate, and a final test on 59 never-used questions, within $2.

**Architecture:** the v3 gate loop is removed. `facts.py` grows the object model, checks, merge and matcher. A new `delivery.py` turns a fact book into what the agent sees for each mode. `learn.py` becomes single-pass discovery. `evaluate.py` runs any mode on any question set, with official and corrected scoring and latency.

### Task 1: Partitions, labels, fact model

- [ ] `split.py`:
  - `pilot_qids(questions)` = the first 15 of the seed-0 order.
  - `make_partitions(questions, v3_split)` returns `{discovery: learn − pilot, gate: test − pilot, final: rest − pilot}`, saved to `runs_v4/partitions.json`.
  - `load_run` returns the partitions.
- [ ] `labels.py`:
  - `download()`: HEAD the raw GitHub URL, print its size, and download to `data/corrected/arcwise_plat_sql_only_with_diff.json` only after the CLI confirms.
  - `corrected(data_dir) -> {qid: sql}`, limited to our database.
  - **Ask the user before the real download.**
- [ ] `facts.py`:
  - `Fact` gains `applies_to: list[str]` and `probe: str | None`; `KINDS` gains `grain` and `relation`.
  - `check_fact` adds: non-empty `applies_to`, and a probe that must be a single SELECT, run read-only and return at least 1 row.
  - `leaks` also scans `applies_to`.
  - `merge(facts, db) -> (facts, conflicts)`: deduplicate on (kind, normalized subject, normalized fact); for a mapping conflict on the same phrase with different `Table.Column` targets, only the one with more `source_qids` keeps the phrase (none on a tie); facts left without phrases are dropped.
- [ ] Tests:
  - partitions: sizes, disjoint, pilot excluded;
  - labels: parsing picks our database's qids, from a fixture file;
  - checks: a probe that fails or returns 0 rows is dropped; empty `applies_to` is dropped;
  - merge: duplicate union and conflict tie-break;
- [ ] Commit `feat: v4 partitions, corrected labels and richer fact model`.

### Task 2: Discovery and delivery modes → review

- [ ] `llm.py`: record `latency_s` (wall time of the API call) in each new reply; `usage["latency_s"]` sums it, cached replays included.
- [ ] `search.py`: `HybridIndex(facts, embed, min_cosine)`. `search(text, k) -> [(Fact, how)]` combines BM25 over the normalized words of applies_to + subject + fact with cosine over the embeddings, fused with RRF (k=60), keeping only facts with BM25 > 0 or cosine ≥ min_cosine. `embed(texts)` calls Ollama `/api/embed` with `qwen3-embedding:0.6b`, cached in `cache/embed/`.
- [ ] `delivery.py`: one small class per mode, with `prompt(question) -> str`, `tools -> list` and `call(name, args) -> str | None`.
  - `NoKnowledge`: empty.
  - `AllFacts(book)`: renders every fact grouped by subject.
  - `Retrieve(book, cap)`: `search(question, cap)` plus all grain and relation facts, rendered.
  - `SearchTool(book, k)`: a manifest line in the prompt, plus the `search_knowledge` tool returning `search(query, k)` with how-matched tags, or "no matching knowledge".
- [ ] `agent.py`:
  - The system prompt uses `knowledge.prompt(question)`.
  - `TOOLS + knowledge.tools` are offered, and `run_tool` tries `knowledge.call` first.
  - `answer` returns `(sql, turns)`; `answer_self_consistent` is removed (self-consistency is out of scope; tag `v3` keeps it).
- [ ] `learn.py`, rewritten to `discover(cfg)`:
  1. docs answers on the discovery set (cache hits);
  2. failures minus known-wrong labels;
  3. v4 proposer prompt (kinds with made-up-shop examples including grain and relation, `applies_to`, optional probe, "one misconception per fact", no skip) in batches of 5;
  4. `check_fact` and batch leakage, then `merge`;
  5. save `runs_v4/knowledge.json`, plus `discover.jsonl` (kept, dropped, conflicts, usage).
  - Delete `learn_loop`, `neutral_fact`, `consolidate` and their tests.
- [ ] CLI: `partition`, `labels`, `discover`.
- [ ] Tests:
  - search (fake embed): BM25 ranks exact phrase matches first; fusion deduplicates a fact found by both and tags it; the relevance floor excludes unrelated facts;
  - delivery: retrieve includes matched facts plus grain/relation within the cap; the tool returns top-k and "no matching knowledge";
  - agent: a `search_knowledge` call is answered by the delivery and counts as a turn;
  - discover (fake LLM): known-wrong-label questions are excluded, dropped facts are logged, the merge is applied.
- [ ] Commit `feat: v4 single-pass discovery and four delivery modes`.
- [ ] **Milestone review** against spec §2–6.

### Task 3: Gate, final test, analysis → review

- [ ] `evaluate.py`:
  - `run_mode(cfg, mode, set_name)` → `runs_v4/{set}_{mode}.jsonl`, with records {qid, sql, correct, correct_corrected, turns, latency_s, knowledge_in_prompt, tool_calls, usage, digest}.
    - Resumable, with the digest check and the Budget kept from v3.
    - Docs uses the same prompt shape as v3, so its answers are cache hits.
  - `gate(cfg)`: runs all/retrieve/tool on the gate set; computes fixes and regressions vs docs; applies the pass rule; writes `runs_v4/gate.json` with the headline mode.
  - `analyze(cfg)` → `results_v4/summary.md`:
    - primary endpoint (headline vs docs on final, official);
    - a per-mode table of accuracy, CI, fixes/regressions, p, corrected accuracy, $, $/correct, p50/p95 latency, turns, knowledge use;
    - the gate table; the knowledge summary and the facts verbatim.
- [ ] CLI: `run --mode {docs,all,retrieve,tool} --set {discovery,gate,final}`, `gate`, `analyze`.
- [ ] README: a v4 section with the command sequence and the arms table.
- [ ] Tests:
  - gate rule (pass/fail and tie order) from fixed records;
  - corrected scoring falls back to official;
  - latency p50/p95 from records;
  - `run_mode` resume with a fake agent.
- [ ] Commit `feat: v4 gate, final test and analysis`.
- [ ] **Milestone review** of the whole of v4 against the spec.
